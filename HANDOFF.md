5. **Вибір вправи** — оверлей `#pickov` (пошук + фільтр обладнання).

## 6. Система планів

### Типи планів
- **`builtin`** (`s.activePlan==='builtin'`) — рекомендований план від тренера, зашитий у `DATA.a`/`DATA.b`,
  з вбудованими фото й аналогами. Не редагується.
- **`generated`** — створений опитуванням усередині додатка.
- **`custom`** — складений користувачем з нуля.

### Структура плану
```json
{ "id":"pXXXX", "name":"Мій план", "type":"custom|generated", "created":"2026-07-23",
  "warmNote":"текст розминки",
  "days":[ { "name":"День 1", "place":"gym|home", "warm":true, "cardio":true,
             "items":[ item ] } ] }
```
`item` (з бібліотеки):
```json
{ "uid":"iXXXX", "libId":"Barbell_Bench_Press...", "name":"...", "ins":["..."],
  "img":"path/0.jpg", "img2":"path/1.jpg", "eq":"barbell", "pm":["chest"],
  "sets":3, "reps":"8–12" }
```
`item` (власна вправа):
```json
{ "uid":"iXXXX", "libId":null, "own":true, "name":"Тяга на моєму тренажері",
  "ins":["опис"], "photoData":"data:image/jpeg;base64,…", "img":null,
  "eq":"machine", "pm":["lats"], "sets":4, "reps":"12", "video":"https://…" }
```
Ключ для логування = `plan.id + ':' + item.uid` (функція `ckey`).

### Опитування → генерація
Питання: мета, днів на тиждень (2/3/4), місце (зал/дім/обидва), обладнання вдома, обмеження
(спина/коліна/плечі/серце/«ноги окремо»), досвід.
Генератор (`generatePlan`):
- шаблони днів `templates(days)` зі «слотів» (`SLOTS`: chest, vpull, hpull, legs, shoulders,
  lowback, core, biceps, triceps);
- фільтр `pickSlot`: обладнання (`equipFor`), рівень, бан-регекс за обмеженнями (`banRe`),
  виключення категорій `plyometrics / olympic weightlifting / strongman / stretching`;
- сортування `exScore`: beginner +3, compound +2, machine +2, body only +1,
  штраф −4 за `decline|behind|guillotine`;
- підходи/повторення за метою (`repScheme`), далі користувач редагує сам;
- «ноги окремо (біг)» прибирає слот legs; «зал+дім» робить останній день домашнім.

### Конструктор
Назва плану, спільна розминка (`warmNote`), дні (назва, зал/дім, тумблери розминки й кардіо),
вправи (порядок ▲▼, видалення ✕, **свої підходи й повторення**), додавання днів і вправ.
Зміни зберігаються одразу (`touch()`).

### Аналоги
Для власних планів рахуються **автоматично** (`altsFor`): та сама головна м'язова група,
**інше обладнання**, не expert, до 2 різних видів інвентарю. Для вбудованого плану — написані вручну.

### Фото офлайн
Кнопка **«⬇ Фото офлайн»** у вкладці «Плани» тягне всі фото плану й кладе в `localStorage`
під ключем **`trener_photos`** (окремо, **не синхронізується**, щоб не роздувати Supabase).
`photoSrc(path)` бере з кешу, інакше — онлайн з `IMG_BASE`.

## 6б. Способи додавання вправ (оверлей `#pickov`)

Кнопка «➕ Додати вправу» в конструкторі відкриває оверлей із 5 режимами (`pickMode`):

| Режим | Як працює | Потребує інтернет |
|---|---|---|
| 🔎 **Пошук** | Фільтр по назві + обладнанню (як було) | так (фото) |
| 💬 **Опис** | `smartFind()` — пошук описом **українською**, офлайн-словник | ні |
| ▶ **Відео** | Посилання YouTube → назва → `smartFind()`; або назва текстом. Будь-яке посилання (у т.ч. Facebook) **зберігається до вправи** | так |
| 📷 **Фото** | Фото → Supabase Edge Function → Claude vision → `smartFind()` | так |
| ✎ **Своя** | Власна вправа: назва, фото з телефона, опис, підходи, м'яз, відео | ні |
| 🎬 **Відео-файл** | Відео **або кілька картинок** → кадри (на пристрої) → ШІ визначає **кілька** вправ → база або «своя» з кадрами | так (ШІ) |

### Пошук описом (`smartFind`)
- Словники: **`UA2EN`** (укр. корінь → англ. слова назви), **`UA2MUS`** (→ м'яз), **`UA2EQ`** (→ обладнання).
- Оцінка: збіг у назві +4, головний м'яз +3, обладнання +3, `beginner` +1, compound +0.5;
  штраф −3 за `decline|behind|guillotine|split|deficit`, бонус за коротшу (канонічнішу) назву.
- Приклади (перевірено): «жим гантелей лежачи» → *Dumbbell Bench Press*;
  «присідання зі штангою» → *Barbell Squat*; «віджимання від підлоги» → *Pushups*.
- Латиниця теж працює (слово додається в пошук як є).

### Відео
`videoTitle(url)` пробує **noembed.com**, потім **youtube.com/oembed**. Якщо CORS блокує —
показує підказку «встав назву відео текстом», і працює той самий `smartFind`.
*(CORS не перевірявся на живому сайті — запасний шлях передбачено.)*

**Facebook / Instagram / TikTok:** назву прочитати неможливо (закритий oEmbed, потрібен токен
застосунку). Для цих хостів одразу показується підказка вставити назву текстом.
Вставлене посилання зберігається в `pickVideoUrl` і при додаванні вправи кладеться в `item.video`,
а картка відкриває саме його (`it.video||ytSearch(it.name)`). Так само працює поле «відео»
у режимі «✎ Своя».

### Своя вправа → особиста бібліотека
Створена вправа зберігається **двічі**:
1. як **шаблон** у `s.myEx[]` (особиста бібліотека, синхронізується);
2. як **екземпляр** у дні плану (`instFromEntry`, поля `own:true`, `ownId`, `photoData`).

Завдяки цьому вона доступна **скрізь**:
- `myExLib()` перетворює `s.myEx` на записи у форматі бібліотеки, `LIBALL()` = `LIB` + свої;
- видно у вкладці «Бібліотека» з міткою «своя» і власним фото (`libImg(x)`);
- працюють фільтри (м'яз/обладнання/рівень) і пошук; у пошуку **описом** для своїх вправ
  додано пряме зіставлення з українською назвою (стем від 4 символів, +6 до оцінки);
- додається в будь-який план і день через ту саму кнопку «➕ Додати в план…»;
- у бібліотеці є кнопка **🗑** — видаляє шаблон із `s.myEx`; уже додані в плани екземпляри
  залишаються (про це попереджає confirm).

Фото стискається `fileToDataURL(file,560)` → JPEG q0.72 і зберігається base64 у стані
(офлайн одразу видно). **v19:** при першому синку (`pushRemote` → `offloadPhotos`) base64
підвантажується у бакет `exphotos` (`{user.id}/{hash}.jpg`, дедуп за хешем), а в полі
лишається публічний URL — тож у `progress.data` більше не летять важкі знімки. Місця читання
(`<img src="${photoData}">`) працюють без змін: URL підставляється замість `data:`-рядка.
Якщо офлайн/бакет не готовий — base64 лишається локально й мігрує сам, коли зʼявиться звʼязок.

### Відео-файл (майстер, модуль mod3) — 3 кроки
Через питання «чи всі вправи потрапили в кадри» майстер зроблено **прозорим**:
1. **Завантаження**: відео (+повзунок густоти 6–24) **та/або кілька картинок** (`#vw-imgs`, multiple)
   + опційне посилання. Картинки стають кадрами напряму (`fileToDataURL(file,640)`, `{src,t:null,img:true}`),
   без нарізки — надійніше за відео. Відео і картинки можна комбінувати в одному проході.
2. **Перегляд** (`stage:'review'`): сітка **всіх** витягнутих кадрів із таймкодами; усі позначені
   за замовчуванням, зайві (розмиті/повтори) можна зняти; видно, скільки позначено. Якщо якоїсь
   вправи не видно — кнопка «‹ Інше відео / більше кадрів» повертає на крок 1 (підняти густоту).
3. **Розпізнавання**: у ШІ йдуть лише позначені кадри, **максимум 8 за прохід** (баланс ціна/якість);
   якщо позначено більше — решта лишається, і після результатів пропонується «ще один прохід».
- `extractFrames(file,count,640)` — до **24** кадрів через `<video>`+canvas, JPEG q0.7, на пристрої;
  кожен кадр — `{src,t}` (t — час у секундах для підпису).
- `aiRecognizeFrames(frames)` → Edge Function з масивом `frames` → `{exercises:[…]}` (кілька вправ,
  кожна з діапазоном `frames:[start,end]`).
- Для кожної: `bestLibMatch(e)` — **потрібен реальний збіг ≥2 слів назви** (не лише мʼяз),
  далі звуження за мʼязом/обладнанням; якщо збігу немає — `framesFor()` бере 1–2 кадри з діапазону
  і створюється **своя вправа** (`s.myEx`, `photoData`+`photo2Data`), і те, і те — з посиланням на відео.
- `openVideoWizard`/`renderVideoWizard`, оверлей `#vidov`, режим у пікері — **🎬 Відео-файл**.
- Edge Function `recognize/index.ts` приймає і `{image}` (одне фото), і `{frames:[…]}` (кілька).
- Обмеження (свідомі): **обрізаного відео не зберігаємо** (тільки кадри-картинки + посилання);
  headless-браузери без H.264 не декодують mp4 — на реальних пристроях кодек є.

### ШІ-розпізнавання (фото)
- Клієнт: `aiRecognize(dataUrl)` → `POST {SUPABASE_URL}/functions/v1/recognize`.
- **Доступ лише залогіненим**: `Authorization: Bearer <access_token>` + `apikey: <publishable>`
  (рекомендований Supabase порядок). `verify_jwt` увімкнено **за замовчуванням** і приймає як
  legacy HS256, так і нові асиметричні токени — окремо налаштовувати нічого не треба.
  Без сесії клієнт кидає `NOT_LOGGED` і запит не надсилається (publishable-ключ **не** йде як Bearer).
- Функція: `recognize/index.ts` (Deno), секрет `ANTHROPIC_API_KEY`, модель за замовчуванням
  `claude-haiku-4-5-20251001` (змінюється секретом `ANTHROPIC_MODEL`).
- Повертає JSON `{name_uk,name_en,equipment,muscle,note}` → результат подається в `smartFind`.
- Інструкція для користувача — **`AI_SETUP.md`**.
- Повідомлення про помилки: `NOT_DEPLOYED`, `NOT_LOGGED`, `NO_CONFIG`, `HTTP_*` — усі
  перекладені в UI.

```json
  "myEx":    [ { "id":"own_xxx", "name":"…", "pm":["lats"], "eq":"machine",
                 "ins":["опис"], "photoData":"data:image/jpeg;base64,…",
                 "photo2Data":"data:image/jpeg;base64,…", "sets":4, "reps":"12", "video":"" } ],
  "activePlan": "builtin|pXXXX",
  "planChosen": true,
  "updated_at": 1718900000000
}
```
- `custom` — вправи, додані з бібліотеки **у вбудований план** (з base64-фото всередині).
- `touch()` — оновлює `updated_at`, зберігає локально, з debounce пушить у Supabase.
- Синхронізація **last-write-wins** за `updated_at`; є Експорт/Імпорт JSON.
- Історія **спільна** для всіх планів, кожен запис містить назву плану.

## 9. Ключові функції (де що шукати в `index.html`)

|---|---|
| `normalize(o)` | нормалізує state (двічі обгорнута: базова + додає `plans/activePlan/planChosen`) |

| `renderPlanDay(p,idx)` | рендер дня власного плану (картки + аналоги + фініш) |

| `wireCard(card)` | навішує ваги/повторення/чекбокс/підказку (спільна для всіх типів карток) |
| `finishDay(d)` / `refreshFinish(d)` | обгорнуті: працюють і для `dN` |
| `renderPlansTab` / `renderSurvey` / `renderBuilder` / `openPicker` | екрани системи планів |
| `generatePlan(a)` / `pickSlot` / `altsFor` | підбір вправ і аналогів |
| `smartFind(text)` / `UA2EN`,`UA2MUS`,`UA2EQ` | пошук вправи описом українською |
| `openAddTo` / `renderAddTo` / `whereAdded` | додавання з бібліотеки в будь-який план і день |
| `myExLib()` / `LIBALL()` / `libImg()` / `instFromEntry()` | особиста бібліотека власних вправ |
| `fileToDataURL(file,maxW)` / `mkCustomItem` | фото з телефона → власна вправа |
| `videoTitle(url)` | назва відео з YouTube (noembed → oembed) |
| `aiRecognize(dataUrl)` | виклик Edge Function розпізнавання (одне фото) |

## 10. Деплой та оновлення

1. Settings → Pages → Deploy from a branch → `main` → `/(root)`.
2. Репозиторій **обов'язково Public** (інакше Pages не публікує).
3. Після зміни — підняти `CACHE='start-u-zali-vN'` (зараз **v24**) і закомітити.
4. На пристрої: **Ctrl+F5 двічі**; у крайньому разі DevTools → Application → Service Workers →
   Unregister / Clear site data.
5. Перевірка: відкрити `.../gym-start/service-worker.js` — має бути актуальна `vN`.

## 11. Відомі підводні камені

- **Приватний репо → Pages вимкнено** (Settings→Pages покаже «Upgrade or make public»).
- **Кеш SW** віддає стару версію → піднімати `vN` + Ctrl+F5 двічі.
- **Деплой у Queued** — новий коміт надійніше за re-run.
- **`index.html` ~1.47 МБ** через base64-фото; за потреби винести фото в теку `img/`.
- **`trener_photos` може переповнити localStorage** при багатьох планах — `savePhotoCache()`
  повертає false і показує тост «Замало місця для всіх фото».
- **Supabase пауcиться після 7 днів** без запитів; після відновлення ключ може змінитися.
- Назви й інструкції вправ з бібліотеки — **англійською** (інтерфейс і фільтри українською).
- Видалення плану **не чистить** його ваги/галочки в state (історія лишається навмисно).
- **(v19) Бакет `exphotos` має бути створений** (`storage_setup.sql`), інакше фото власних вправ
  не вивантажуються: на цьому пристрої вони видно (base64 локально), але на інші не потраплять,
  доки бакет не зʼявиться. Помилки офлоаду мовчазні (per-field try) — стан не ламається.

## 13. Перевірено тестами (Playwright)

Створення власного плану, вибір вправ через пошук, зміна підходів/повторень, рендер дня з
аналогами, логування ваги й повторень, запис у історію з назвою плану, опитування → генерація
(3 дні, обмеження спина/серце/ноги), перемикання на вбудований план, збереження після
перезавантаження, кеш офлайн-фото (24 шт.), відсутність JS-помилок, верстка без переповнення на 360px.

Додатково (v11–v16): 5 режимів додавання вправ; пошук описом українською на 6 запитах;
збіг за назвою відео; своя вправа з фото (прев'ю, збереження base64, мітка «своя», автоаналоги);
коректні повідомлення ШІ-режиму при ненастроєному Supabase.
Картинки в майстрі (v18): 3 фото → 3 кадри з міткою «фото» → розпізнано 2 вправи (одна з бази,
одна «своя»); змішаний режим (6 кадрів відео + 2 фото = 8) працює; підписи різняться (час / «фото»).

Відео-майстер (v16→v17): триетапний майстер; витягання 12 і 20 кадрів; усі позначені за
замовчуванням; таймкоди; зняття позначок (12→6); розпізнавання лише з обраних; підбір у базі
(2 вправи) з прикріпленим відео; повернення на крок «більше кадрів»; верстка сітки без
переповнення на 360px. (H.264/mp4 у headless не декодується — перевірено на webm; на телефоні є.)

Особиста бібліотека (v15): своя вправа зберігається в `s.myEx`, знаходиться в бібліотеці за
українською назвою і через фільтр м'яза, має мітку «своя» і власне фото, додається в інший план
(перевірено План A → План B), у пошуку описом стає першою за своєю назвою; видалення з бібліотеки
не ламає вже додані екземпляри.

Додавання з бібліотеки (v14): крок «план» → крок «день», додавання у власний план (День 2)
і у вбудований (День B, фото вбудовано base64), мітка «Уже в:», блокування дубля.

Режим «Відео» перевірено з підміненою мережею: розбір `watch?v=`, `youtu.be`, `/shorts/`,
`m.youtube.com`; збіг за англійськими, українськими та змішаними назвами; запасний шлях при
блокуванні мережі; збереження Facebook-посилання у вправу й відкриття його з картки.

**Не перевірено наживо:** ШІ-розпізнавання (потребує задеплоєної функції та платного ключа)
і реальний CORS для читання назви відео з YouTube.
